# アプリアイコン刷新 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 通知アイコンの流用をやめ、Adaptive Icon の仕様に沿った専用のランチャーアイコン（foreground / background / monochrome）と、それに揃えた通知アイコンを作る。

**Architecture:** すべて Vector Drawable (XML) で実装する。ラスター画像を一切持たないため `mipmap-*dpi` ディレクトリは作らない。ランチャーの foreground と通知アイコンはキャンバスサイズ（108dp / 24dp）が異なり最適な線幅も違うため、別ファイルとして独立させる。monochrome レイヤーは `fillType="evenOdd"` を使い、本としおりを 1 つのパスにまとめてしおり部分を抜き穴として表現する。

**Tech Stack:** Android Vector Drawable, Adaptive Icon (`mipmap-anydpi-v26`), Gradle 9.x, AGP

**設計の出典:** `docs/superpowers/specs/2026-08-21-app-icon-design.md`

## Global Constraints

- キャンバスは 108dp（`viewportWidth` / `viewportHeight` ともに 108）。可視域は中央 72dp、保証される安全領域は中心 (54,54) から半径 33dp。
- 配色は 背景 `#3B5998` / 本 `#F9F9FF` / 本の背 `#B4C5E4` / しおり `#D8503F` に固定する。
- `minSdk` は 28。`mipmap-anydpi-v26` のみで全端末をカバーするため、レガシー PNG mipmap を追加してはならない。
- `AndroidManifest.xml` は `android:roundIcon` を参照していない。追加してはならない。
- 通知アイコンのリソース名は `ic_notification` のまま据え置く。`ArticleNotificationSender` のコードは変更しない。
- コミットメッセージは Conventional Commits 形式。`Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>` を付与する。
- ソースコード中のパスデータに座標の意味を説明するコメントを入れない（Vector Drawable の XML にコメントを入れるとビルドツールが警告を出すことがあるため、意図は本計画と spec に残す）。

## テスト方針

Vector Drawable は宣言的なリソースであり、振る舞いとして表現できるテストが存在しない。XML を読んでパス文字列を照合するテストは tautological であり、書いてはならない。検証は次の 3 段で行う。

1. `assembleStagingDebug` が通ること（XML として妥当で、参照が解決すること）
2. `lintStagingDebug` が通ること（Adaptive Icon 関連の Lint 指摘が出ないこと）
3. 実際にレンダリングした画像の目視確認（Task 4）

### Task 2: monochrome レイヤーの追加

**Files:**
- Create: `app/src/main/res/drawable/ic_launcher_monochrome.xml`
- Modify: `app/src/main/res/mipmap-anydpi-v26/ic_launcher.xml`

**Interfaces:**
- Consumes: Task 1 で確定した本としおりのパスデータ
- Produces: `@drawable/ic_launcher_monochrome`

**設計意図:** monochrome レイヤーはシステムが単色で塗り潰すため、色による要素分離が一切効かない。本としおりを 1 つのパスにまとめて `fillType="evenOdd"` を適用すると、本と重なる範囲のしおりは塗りが打ち消されて抜き穴になり、本からはみ出した尾（`y=78` 以下）は塗りが残る。結果としてしおりは「本の上では負の空間、本の下では実体」として読め、追加のヘアラインを描かずに分離できる。抜き穴の幅はしおりの幅そのもの（12dp）なので、48dp 表示でも約 5px あり潰れない。

- [ ] **Step 1: monochrome の Vector Drawable を作成する**

`app/src/main/res/drawable/ic_launcher_monochrome.xml`:

```xml
<?xml version="1.0" encoding="utf-8"?>
<vector xmlns:android="http://schemas.android.com/apk/res/android"
    android:width="108dp"
    android:height="108dp"
    android:viewportWidth="108"
    android:viewportHeight="108">
    <path
        android:fillColor="#FFFFFF"
        android:fillType="evenOdd"
        android:pathData="M37,25 H71 A3,3 0 0 1 74,28 V75 A3,3 0 0 1 71,78 H37 A3,3 0 0 1 34,75 V28 A3,3 0 0 1 37,25 Z M58,0 H70 V87 L64,80 L58,87 Z" />
</vector>
```

`android:fillColor` はシステムのティントで置き換えられるが、Vector Drawable の仕様上いずれかの色指定が必須のため `#FFFFFF` を置く。

- [ ] **Step 2: ic_launcher.xml に monochrome レイヤーを追加する**

`app/src/main/res/mipmap-anydpi-v26/ic_launcher.xml` を次の内容に置き換える。

```xml
<?xml version="1.0" encoding="utf-8"?>
<adaptive-icon xmlns:android="http://schemas.android.com/apk/res/android">
    <background android:drawable="@color/ic_launcher_background" />
    <foreground android:drawable="@drawable/ic_launcher_foreground" />
    <monochrome android:drawable="@drawable/ic_launcher_monochrome" />
</adaptive-icon>
```

- [ ] **Step 3: monochrome のシルエットをレンダリングして目視確認する**

```bash
rsvg-convert -w 192 -h 192 /tmp/icon-evidence/mono.svg -o /tmp/icon-evidence/mono-192.png
```

**背景:** `ic_notification.xml` は app と core:data の 2 箇所に同名で存在し、内容は完全に一致している。通知を送出するのは core:data だが、リソースマージでは app モジュールが優先されるため、実際に表示されているのは app 側の定義である。Task 1 でランチャーが app 側を参照しなくなったので、ここで削除できる。

- [ ] **Step 2: core:data 側の通知アイコンを新シルエットに差し替える**

`core/data/src/main/res/drawable/ic_notification.xml`:

```xml
<?xml version="1.0" encoding="utf-8"?>
<vector xmlns:android="http://schemas.android.com/apk/res/android"
    android:width="24dp"
    android:height="24dp"
    android:viewportWidth="24"
    android:viewportHeight="24"
    android:tint="#FFFFFF">
    <path
        android:fillColor="@android:color/white"
        android:fillType="evenOdd"
        android:pathData="M8,4 H16 A1,1 0 0 1 17,5 V16 A1,1 0 0 1 16,17 H8 A1,1 0 0 1 7,16 V5 A1,1 0 0 1 8,4 Z M12,4 H15 V20 L13.5,18 L12,20 Z" />
```

`ArticleNotificationScheduler` は `PeriodicWorkRequestBuilder` を初期遅延なしで `enqueueUniquePeriodicWork` している（`core/data/src/main/java/blue/starry/tokidokiroppou/core/data/worker/ArticleNotificationScheduler.kt:17-27`）。WorkManager は制約を満たした周期ワークの初回実行を即座に走らせるため、設定画面で通知トグルを ON にすれば数秒以内に通知が発火する。テスト通知専用のボタンは実装されていないので、この経路を使う。

```bash
export ANDROID_HOME="$HOME/Android/Sdk"
ADB="$ANDROID_HOME/platform-tools/adb"
"$ADB" shell pm grant blue.starry.tokidokiroppou.staging android.permission.POST_NOTIFICATIONS
"$ADB" shell monkey -p blue.starry.tokidokiroppou.staging -c android.intent.category.LAUNCHER 1
sleep 5
"$ADB" exec-out uiautomator dump /dev/tty | tr '>' '\n' | grep -i "設定\|Switch"
```

Expected: 設定タブと通知トグルの `bounds` 属性が読み取れる。その座標の中心を `adb shell input tap <x> <y>` でタップして設定画面へ移動し、通知トグルを ON にする。座標は画面解像度に依存するため、必ず `uiautomator dump` の出力から算出すること。

トグルを ON にした後、通知を確認する。

```bash
export ANDROID_HOME="$HOME/Android/Sdk"
ADB="$ANDROID_HOME/platform-tools/adb"
sleep 20
"$ADB" shell cmd statusbar expand-notifications
sleep 2
"$ADB" exec-out screencap -p > /tmp/icon-evidence/notification-after.png && echo done
```

Expected: `done`。通知シェードに新しい本＋しおりのアイコンが表示される。20 秒待っても通知が出ない場合は `"$ADB" logcat -d | grep -i "ArticleNotification"` でワーカーの実行状況を確認する。それでも発火しない場合は、この Step の証跡を Task 3 Step 4 のオフラインレンダリングで代替し、「通知の実表示は未検証」と明記して報告する。
