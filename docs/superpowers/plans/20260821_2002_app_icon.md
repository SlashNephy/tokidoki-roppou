# アプリアイコン刷新 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 通知アイコンの流用をやめ、Adaptive Icon の仕様に沿った専用のランチャーアイコン（foreground / background / monochrome）と、それに揃えた通知アイコンを作る。

**Architecture:** すべて Vector Drawable (XML) で実装する。ラスター画像を一切持たないため `mipmap-*dpi` ディレクトリは作らない。（**2026-08-22 追記:** 外部コンシューマ向けのレガシー PNG mipmap は後から追加した。ただし Vector Drawable から機械的に焼き出すもので、図像の出所は依然として XML ただ一つ。）ランチャーの foreground と通知アイコンはキャンバスサイズ（108dp / 24dp）が異なり最適な線幅も違うため、別ファイルとして独立させる。monochrome レイヤーは `fillType="evenOdd"` を使い、本としおりを 1 つのパスにまとめてしおり部分を抜き穴として表現する。

**Tech Stack:** Android Vector Drawable, Adaptive Icon (`mipmap-anydpi-v26`), Gradle 9.x, AGP

**設計の出典:** `docs/superpowers/specs/2026-08-21-app-icon-design.md`

## Global Constraints

- キャンバスは 108dp（`viewportWidth` / `viewportHeight` ともに 108）。可視域は中央 72dp、保証される安全領域は中心 (54,54) から半径 33dp。
- 配色は 背景 `#3B5998` / 本 `#F9F9FF` / 本の背 `#B4C5E4` / しおり `#D8503F` に固定する。
- `minSdk` は 28。端末上は `mipmap-anydpi-v26` のみで全端末をカバーする。レガシー PNG mipmap は、端末のためではなく Firebase App Distribution など APK からアイコンを取り出す外部のコンシューマ向けに出荷する。（**2026-08-22 追記:** 当初この項は「レガシー PNG mipmap を追加してはならない」だったが撤回した。設計書の該当追記と `docs/superpowers/assets/icon/README.md` を参照。）
- `AndroidManifest.xml` は `android:roundIcon` を参照していない。追加してはならない。
- 通知アイコンのリソース名は `ic_notification` のまま据え置く。`ArticleNotificationSender` のコードは変更しない。
- コミットメッセージは Conventional Commits 形式。`Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>` を付与する。
- ソースコード中のパスデータに座標の意味を説明するコメントを入れない（Vector Drawable の XML にコメントを入れるとビルドツールが警告を出すことがあるため、意図は本計画と spec に残す）。

## テスト方針

Vector Drawable は宣言的なリソースであり、振る舞いとして表現できるテストが存在しない。XML を読んでパス文字列を照合するテストは tautological であり、書いてはならない。検証は次の 3 段で行う。

1. `assembleStagingDebug` が通ること（XML として妥当で、参照が解決すること）
2. `lintStagingDebug` が通ること（Adaptive Icon 関連の Lint 指摘が出ないこと）
3. 実際にレンダリングした画像の目視確認（Task 4）

- [x] **Step 2: 前景の Vector Drawable を作成する**

`app/src/main/res/drawable/ic_launcher_foreground.xml`:

```xml
<?xml version="1.0" encoding="utf-8"?>
<vector xmlns:android="http://schemas.android.com/apk/res/android"
    android:width="108dp"
    android:height="108dp"
    android:viewportWidth="108"
    android:viewportHeight="108">
    <path
        android:fillColor="#F9F9FF"
        android:pathData="M39,31 H69 A3,3 0 0 1 72,34 V74 A3,3 0 0 1 69,77 H39 A3,3 0 0 1 36,74 V34 A3,3 0 0 1 39,31 Z" />
    <path
        android:fillColor="#B4C5E4"
        android:pathData="M39,31 H42 V77 H39 A3,3 0 0 1 36,74 V34 A3,3 0 0 1 39,31 Z" />
    <path
        android:fillColor="#D8503F"
        android:pathData="M58,31 H67 V71 L62.5,66 L58,71 Z" />
</vector>
```

3 つのパスの意味は順に、本（36×46dp、角丸 3dp）、本の背（左端 6dp）、しおり（幅 9dp、上端 `y=31` は本の上辺と一致、下端 `y=71`、V ノッチ頂点 `(62.5,66)`。本から突出させない）。

安全領域への収まりは、アイコン中心 (54,54) から各頂点までの距離で判定すること。本の中心からの距離ではない。角丸の頂点は、鋭角の頂点ではなくアークの中心までの距離に角丸半径を足して求めること。最外点は本の四隅がいずれも 28.0dp（アーク中心まで 25.0dp + 半径 3dp）。しおりは本の内側に完全に収まる。本は水平・垂直とも中央に置く。

### Task 2: monochrome レイヤーの追加

**Files:**
- Create: `app/src/main/res/drawable/ic_launcher_monochrome.xml`
- Modify: `app/src/main/res/mipmap-anydpi-v26/ic_launcher.xml`

**Interfaces:**
- Consumes: Task 1 で確定した本としおりのパスデータ
- Produces: `@drawable/ic_launcher_monochrome`

**設計意図:** monochrome レイヤーはシステムが単色で塗り潰すため、色による要素分離が一切効かない。本としおりを 1 つのパスにまとめて `fillType="evenOdd"` を適用すると、しおりは本と完全に重なるため塗りが打ち消され、V ノッチを持つ抜き穴になる。追加のヘアラインを描かずに分離できる。抜き穴の幅はしおりの幅そのもの（9dp）なので、48dp 表示でも約 4px あり潰れない。

- [x] **Step 1: monochrome の Vector Drawable を作成する**

`app/src/main/res/drawable/ic_launcher_monochrome.xml`:

```xml
<?xml version="1.0" encoding="utf-8"?>
<vector xmlns:android="http://schemas.android.com/apk/res/android"
    android:width="108dp"
    android:height="108dp"
    android:viewportWidth="108"
    android:viewportHeight="108">
    <path
        android:fillColor="#FFFFFF"
        android:fillType="evenOdd"
        android:pathData="M39,31 H69 A3,3 0 0 1 72,34 V74 A3,3 0 0 1 69,77 H39 A3,3 0 0 1 36,74 V34 A3,3 0 0 1 39,31 Z M58,31 H67 V71 L62.5,66 L58,71 Z" />
</vector>
```

`android:fillColor` はシステムのティントで置き換えられるが、Vector Drawable の仕様上いずれかの色指定が必須のため `#FFFFFF` を置く。

- [x] **Step 2: ic_launcher.xml に monochrome レイヤーを追加する**

- [x] **Step 2: core:data 側の通知アイコンを新シルエットに差し替える**

`core/data/src/main/res/drawable/ic_notification.xml`:

```xml
<?xml version="1.0" encoding="utf-8"?>
<vector xmlns:android="http://schemas.android.com/apk/res/android"
    android:width="24dp"
    android:height="24dp"
    android:viewportWidth="24"
    android:viewportHeight="24"
    android:tint="#FFFFFF">
```

- [x] **Step 7: 通知の実表示を確認する**

テスト通知専用のボタンは実装されていないため、設定画面の通知トグルを ON にして `ArticleNotificationScheduler`（`core/data/src/main/java/blue/starry/tokidokiroppou/core/data/worker/ArticleNotificationScheduler.kt`）に周期ワークを積ませる経路を使う。

ただし `PeriodicWorkRequest` の初回実行は「制約を満たし次第」であって時刻の保証はない。固定時間の `sleep` で成否を判定してはならない。さらに `ArticleNotificationWorker` は条文を取得できなかった場合に `Result.retry()` を返す（`ArticleNotificationWorker.kt:35`）ため、通知が出ないことだけを根拠にワーカー未実行と判断することもできない。ワーカーの実行結果と通知の表示は分けて確認する。

まずアプリを起動し、設定画面を開く。

```bash
export ANDROID_HOME="$HOME/Android/Sdk"
export ANDROID_SERIAL=emulator-5556
ADB="$ANDROID_HOME/platform-tools/adb"
PKG=blue.starry.tokidokiroppou.staging
"$ADB" shell pm grant $PKG android.permission.POST_NOTIFICATIONS
"$ADB" shell am start -n $PKG/blue.starry.tokidokiroppou.MainActivity
sleep 9
"$ADB" shell input tap 1006 220
sleep 6
"$ADB" exec-out screencap -p > /tmp/icon-evidence/settings.png
```

Expected: `settings.png` に設定画面が写る。「通知を有効にする」のスイッチの座標をこのスクリーンショットから読み取ってタップする（1080×2400 では概ね `(975, 500)`）。画面解像度が異なる場合は `"$ADB" shell wm size` で確認して調整する。

トグルを ON にしたら、ワーカーの実行結果をログで確認する。時間で待つのではなく、ログの出現をポーリングする。

```bash
export ANDROID_HOME="$HOME/Android/Sdk"
export ANDROID_SERIAL=emulator-5556
ADB="$ANDROID_HOME/platform-tools/adb"
"$ADB" shell input tap 975 500
for i in $(seq 1 30); do
  L=$("$ADB" shell logcat -d -t 800 2>/dev/null | grep -E "ArticleNotificationSender: Sent notification|ArticleNotificationWorker")
  if echo "$L" | grep -q "Sent notification"; then echo "SENT"; echo "$L" | tail -3; break; fi
  sleep 10
done
```

Expected: `ArticleNotificationSender: Sent notification: <条文>` が出力される。`ArticleNotificationWorker started` は出るが `Sent notification` が出ない場合は条文の取得に失敗しており（`Result.retry()`）、通知アイコンの問題ではない。この場合は法令キャッシュの取得完了を待ってから再試行する。

送出を確認したら通知シェードを撮る。

```bash

export ANDROID_SERIAL=emulator-5556
ADB="$ANDROID_HOME/platform-tools/adb"
"$ADB" shell input keyevent KEYCODE_HOME; sleep 2
"$ADB" shell cmd statusbar expand-notifications; sleep 4
"$ADB" exec-out screencap -p > /tmp/icon-evidence/notification-after.png
"$ADB" shell cmd statusbar collapse; sleep 3
"$ADB" exec-out screencap -p > /tmp/icon-evidence/statusbar.png
echo done
```

Expected: `done`。通知シェードとステータスバーの双方に新しい本＋しおりのアイコンが表示される。

30 回ポーリングしても送出されない場合は、この Step の証跡を Task 3 Step 4 のオフラインレンダリングで代替し、「通知の実表示は未検証」と明記して報告する。
